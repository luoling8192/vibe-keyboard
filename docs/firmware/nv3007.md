# NV3007 Panel Profile

Status: Binary-recovered from vendor `voice_stick` 0.3.8, including startup and panel power methods

## Reset and Backlight

Reset is active-low on GPIO12:

```text
configure output
→ low
→ delay 100 ms
→ high
→ delay 100 ms
```

Backlight is active-high LEDC PWM on GPIO9:

```text
mode: low speed
channel: 0
timer: 0
resolution: 8 bit
frequency: 5000 Hz
initial duty: 128
normal ready duty: 255
```

## Addressing and Pixels

The panel draw function applies:

```text
controllerX = logicalX
controllerY = logicalY + 14
```

It sends `CASET 0x2a`, `RASET 0x2b`, then `RAMWR 0x2c`. Coordinate bytes are big-endian.

Initialization contains:

```text
MADCTL 0x36 = 0x60  // MIPI MX | MV, RGB bit ordering
COLMOD 0x3a = 0x05  // RGB565
```

The startup path has no recovered `INVON 0x21`. LVGL stores native RGB565 and the display port sets `swap_bytes=true` before SPI transfer.

## Startup and Panel Power

Replacement startup order:

```text
reset GPIO12 low
  → wait 100 ms
  → reset GPIO12 high
  → wait 100 ms
  → send all 119 initialization entries
  → final SLPOUT 0x11
  → wait 220 ms
  → send DISPON 0x29 through the panel power method
  → add the LVGL display
  → set backlight duty to 255
  → initialize higher-level UI
```

The replacement driver must not append `DISPON 0x29` to the recovered initialization table. The board lifecycle invokes the panel method explicitly, propagates the first GPIO or panel-I/O failure, and sends `DISPOFF 0x28` during reverse-order cleanup.

The recovered panel methods are:

| Operation | Command | Parameters | Driver delay |
|---|---:|---|---:|
| display on | `0x29` | none | none |
| display off | `0x28` | none | none |
| wake / sleep out | `0x11` | none | none |
| sleep in | `0x10` | none | none |

The vendor methods do not delay and discard the underlying `tx_param` error. Replacement firmware must return the real `esp_err_t`. A wake caller owns the proven 220 ms delay before restoring display/backlight state.

Recommended screen power policy keeps panel commands and backlight explicit:

```text
display off → send 0x28 → set backlight 0
display on  → send 0x29 → restore configured backlight
sleep       → send 0x10 → set backlight 0
wake        → send 0x11 → wait 220 ms → restore display/backlight state
```

The backlight ordering in this policy is replacement-firmware behavior. The panel command bytes and initialization-table order are recovered vendor behavior.

## LVGL 9 Port

```text
LVGL task priority: 5
LVGL task stack: 8192
CPU affinity: -1
maximum sleep: 500 ms
timer period: 5 ms
```

Display buffers:

```text
buffer pixels: 4280 (10 rows)
double buffer: true
buffer bytes: 2 × 8560
DMA-capable: true
PSRAM-enabled: true
color format: LV_COLOR_FORMAT_RGB565
swap bytes: true
software rotate: false
full refresh: false
direct mode: false
```

With software rotation disabled, pinned `esp_lvgl_port` 2.8.0~1 applies rotation zero by calling `swap_xy(false)` and `mirror(false, false)`. The replacement panel driver treats only those exact no-op requests as success because orientation is already established by recovered MADCTL `0x60`; requests that would mutate orientation remain `ESP_ERR_NOT_SUPPORTED` and send no panel command.

## Evidence Limit

Register byte values, startup control flow, and panel power-method command bytes are recovered from the target firmware. Private-register semantics are not claimed without an NV3007 datasheet. Physical orientation, color, gaps, and backlight still require a replacement-firmware test pattern before acceptance; this runtime test validates the recovered profile rather than authorizing guessed commands.
